# Aurora Saigon: luxury jewellery storefront

Next.js 15 (App Router) + TypeScript + Tailwind 4, Framer Motion, Lenis smooth scroll, Zustand. 418 products shown from `src/data/products.json` (419 scraped; **AS-039 is hidden**: its only surviving image is a "White Topaz" text card). Payments (VietQR, card/AlePay/Stripe), the cart, the newsletter and both booking forms are **demos**: nothing is sent or stored, and the UI says so. Keep it that way until real backends exist.

Not a git repo. Windows + OneDrive. Dev: `npm run dev` (port 3000). **Stop the dev server before `next build`** (they corrupt `.next`). Never invent facts, grades, photos, lengths or reviews: if the live site does not say it, the storefront does not either.

## Design philosophy: quiet luxury
Editorial, magazine-standard, generous whitespace, nothing decorative that does not earn its place. Sections are separated by whitespace on one ground, not by rules or borders.
- **Fonts:** Cormorant Garamond 300/400 + italic = `font-display` (headlines, prices, titles). Inter 300/400/500 = `font-sans` (UI, body). Body bold = weight 500 + full obsidian.
- **Motion:** slow `cubic-bezier(0.22,1,0.36,1)`; restrained reveals; never `linear`/`ease-in-out`. Videos autoplay only while on screen and never under reduced motion.
- **No AI-slop (impeccable rules):** no kicker/eyebrow label above a heading, no icon-heading-text card grids, no gradient text, no glow shadows, no unicode glyphs as icons (draw them), no decorative blur, no coloured side borders. Glass is only for the floating header (`.glass`). (The Ring Anatomy 01/02/03 numbers and the 5 Reasons numerals are owner-requested exceptions.)
- **Contrast:** small text must reach 4.5:1. Never put `text-champagne` (2.4:1) on the light ground except decorative large numerals/stars.
- **Read mode (policy/blog text):** 36rem measure (~70ch), heading scale in `article-body.tsx`, source bold kept as `**markers**`.

## The photo-ground rule (hard-won; do not regress)
Product photos are the **original studio photos** in `public/scraped-images/`, untouched. **Never run background removal / cutouts again** (it ate gold shanks and claws).
Photos have lighting falloff and backdrops about `#D7CFC1`, darker than the page. Measured consequences:
- Plain `mix-blend-mode: multiply` cannot hide a photo edge (it only vanishes against white). It works only when the photo is first graded to **white** (hero) so multiply lands on the page colour.
- **Catalog cards:** square photos fill the card on `bg-cream` with multiply. Tiles are visible by nature; accepted.
- **Modal stage / graded images:** `useGain` samples the backdrop in the browser; an SVG `feComponentTransfer` lifts it to the target ground; a 10% edge feather (36% on top for shadow-band photos) dissolves edges. Macro frames are not graded. The magnifier (1.7x) engages only over the stone after real pointer travel (>6 px).
- Verified: left/right ground diff 0, edge step < 1 on front/angle views; hero rest state equals the page colour exactly.

## Supabase catalogue (the only runtime data source)
Every product is one row of Supabase `products` (`supabase/schema.sql`, RLS: public read, writes only via service role). `scripts/migrate-to-supabase.js` (`npm run migrate:supabase`) loads the JSON into it: scalar columns + JSONB `images`, `available_metals`, `available_karats`, `metal_pricing` (MULTIPLIERS of `price_vnd`, so one price edit re-prices every metal/karat), `gallery`, `attributes`, `chain_lengths`. A re-run keeps `is_sold` and edited `price_vnd` (`--reset-prices` overwrites). Hidden AS-039 is simply not migrated. `lib/product-model.ts` `fromRow()` turns a row into the slim `Product` (verified identical to the old JSON path for all 418 pieces). `lib/catalog.ts` `getCatalog()` (server, cached 60 s, tag `catalog`) feeds the pages; if Supabase errors or returns 0 rows it **falls back to the bundled `products.json`** (converted by `lib/product-rows.ts`, the same row builder the migration uses) so the storefront is never blank; the log says `[catalog] Supabase unavailable`. The page revalidates every 60 s so a recovered database is picked up. `use-live-catalog.ts` (client) fetches rows changed since render and subscribes to Realtime into `store.live`, which overrides the server copy in the grid AND the open modal. Sold = hidden from Ready to Ship, "Sold / Atelier archive" elsewhere, not purchasable. `/admin/inventory`: edit `price_vnd` and toggle `is_sold` for any piece; closed unless `ADMIN_PASSWORD` (8+), `ADMIN_SESSION_SECRET` (32+, no fallback), `SUPABASE_SERVICE_ROLE_KEY` are set. See `.env.example`. Gotcha: a stray `Supabase:` line in `.env.local` makes dotenv swallow the next variable; comment lines need `#`.

## Gotchas
- **OneDrive locks `.next`** (`EBUSY ... next-font-manifest.json` -> every route 500). Fix: stop the server, `rm -rf .next`, restart. Pausing OneDrive sync or moving the project out of OneDrive prevents it.
- The dev server compiles each new route on first visit (slow). Rewriting `src/data/*.json` while it runs causes transient "Unexpected end of JSON input" errors; they clear on the next compile.
- `.next/types` errors from `tsc` right after adding a route are dev-server regeneration, not source errors; re-run after a few seconds.
- A Next page file may not export extra helpers (build error); keep helpers in components or local.
